# MVP Calculator — Пользовательские сценарии

## Сценарий 1: Регистрация нового пользователя

1. Пользователь открывает главную страницу `/`
2. Нажимает кнопку **«Попробовать бесплатно»** в Hero-секции
3. Переходит на страницу `/register`
4. Заполняет поля: Имя (опционально), Email, Пароль (мин. 6 символов)
5. Нажимает **«Зарегистрироваться»**
6. Валидация формы (react-hook-form + Zod):
   - Если email некорректный — показывается ошибка
   - Если пароль < 6 символов — показывается ошибка
7. Вызывается `supabase.auth.signUp()` → пользователь создаётся в `auth.users`
8. Срабатывает триггер `handle_new_user()` → автоматически создаётся запись в `profiles`:
   - `is_admin = false`
   - `subscription_tier = 'free'`
   - `project_limit = 3`
   - `custom_services_limit = 2`
9. Пользователь видит toast **«Регистрация успешна! Проверьте email для подтверждения.»**
10. Редирект на `/login`

---

## Сценарий 2: Вход в систему

1. Пользователь открывает `/login`
2. Заполняет Email и Пароль
3. Нажимает **«Войти»**
4. Валидация формы:
   - Некорректный email → ошибка
   - Пароль < 6 символов → ошибка
5. Вызывается `supabase.auth.signInWithPassword()`
6. При успехе:
   - Toast **«Вход выполнен»**
   - Редирект на `/dashboard`
7. При ошибке (неверные данные):
   - Toast с сообщением об ошибке от Supabase

---

## Сценарий 3: Просмотр лендинга (неавторизованный)

1. Пользователь открывает `/`
2. Видит:

   - Футер с копирайтом и ссылками
3. Нажимает **«Войти»** → `/login`
4. Нажимает **«Попробовать бесплатно»** → `/register`

## Сценарий 4: Просмотр лендинга (авторизованный)

1. Пользователь открывает `/`
2. В хедере видит кнопку **«Дашборд»** и кнопку **«Выйти»**
3. Нажимает **«Дашборд»** → `/dashboard`

## Сценарий 5: Дашборд — первый вход

1. Пользователь входит в систему → редирект на `/dashboard`
2. Видит:
   - Приветствие по имени (`full_name`) или email
   - Карточку **«Лимит проектов»**: тариф `free`, прогресс-бар «Создано 0 из 3»
   - Кнопку **«Создать новый проект»** (активна)
   - Сообщение **«У вас пока нет проектов»** с кнопкой «Создать первый проект»
3. Видит Header с навигацией: Дашборд, Настройки, Тарифы, переключатель темы, кнопка «Выйти»

---

## Сценарий 6: Создание нового проекта (полный поток)

1. На дашборде нажимает **«Создать новый проект»**
2. Переходит на `/projects/new` → открывается пошаговый конструктор

### Шаг 1: Описание
3. Вводит **название проекта** (обязательное) и опциональное описание
4. Счётчик символов обновляется
5. Кнопка **«Далее»** активна только при заполненном названии
6. Нажимает **«Далее»**

### Шаг 2: Выбор сервисов
7. Видит сетку из 10 стандартных сервисов (иконка + название)
8. Кликает на карточки → они меняют цвет (выбрано/не выбрано)
9. Видит кастомные сервисы (если создал ранее)
10. Нажимает **«Далее»** (активна если выбран хотя бы 1 сервис)

### Шаг 3: Технологии
11. Выбирает из выпадающих списков:
    - Фронтенд (React/Vue/Angular)
    - Бэкенд (Node.js/Python/Ruby/PHP)
    - База данных (PostgreSQL/MySQL/MongoDB)
    - Мобильная разработка (React Native/Flutter/Native iOS/Native Android/Не требуется)
12. Значения по умолчанию: React, Node.js, PostgreSQL
13. Нажимает **«Далее»**

### Шаг 4: Состав команды
14. Видит 7 ролей с чекбоксами
15. Отмечает нуж роли → появляется поле ввода количества человек
16. Видит общую статистику «Всего человек: N»
17. Нажимает **«Далее»** (активна если выбрана хотя бы 1 роль)

### Шаг 5: Саммари
18. Видит сводку:
    - Название проекта
    - Выбранные сервисы (бейджи)
    - Технологии (карточка)
    - Команда (список ролей с количеством)
19. Нажимает **«Рассчитать»**
20. Отправляется `POST /api/calculate`
21. При успехе:
    - Toast **«Расчёт выполнен! Переход на страницу результата...»**
    - Если редактирование существующего проекта → редирект на `/projects/[id]/result`
    - Если новый проект → toast **«Сохраните проект, чтобы получить страницу результата»**

## Сценарий 7: Страница результата

1. Пользователь переходит на `/projects/[id]/result`
2. Загружается расчёт (или из сохранённого проекта, или пересчитывается)
3. Видит:
   - Верхнюю панель с кнопками **«Сохранить проект»** и **«Экспорт в PDF»**
   - Бейдж статуса: «Черновик» / «Сохранён»
   - Сводные карточки: Стоимость, Человеко-часы, Календарное время, Кол-во сервисов
   - Карточку с технологиями
   - Таблицу сервисов (название, часы, стоимость)
   - Таблицу ролей (роль, ставка, часы, коэффициент, стоимость)
   - Круговую диаграмму (PieChart) распределения стоимости по ролям
4. Нажимает **«Сохранить проект»**:
   - `PUT /api/projects/[id]` с `status='completed'` и полным снимком данных
   - Toast **«Проект сохранён»**
   - Бейдж меняется на «Сохранён»
5. Нажимает **«Экспорт в PDF»**:
   - `POST /api/export/pdf`
   - Скачивается файл `project-name.pdf`
   - Для бесплатного тарифа — водяной знак «MVP Calculator Demo»
   - Toast **«PDF скачан»**

---

## Сценарий 8: Редактирование проекта

1. На дашборде в карточке проекта нажимает **«⋮»** → **«Редактировать»**
2. Переходит на `/projects/[id]/edit`
3. Загружаются данные проекта из БД → заполняется Zustand store
4. Пользователь меняет параметры на любом шаге
5. Переходит на шаг 5 → нажимает **«Рассчитать»**
6. Редирект на `/projects/[id]/result` с обновлёнными данными
7. Нажимает **«Сохранить проект»** → обновляется запись в БД

---

## Сценарий 9: Удаление проекта

1. На дашборде в карточке проекта нажимает **«⋮»** → **«Удалить»**
2. Открывается модальное окно с предупреждением
3. Нажимает **«Удалить»**
4. Вызывается `DELETE /api/projects/[id]`
5. При успехе:
   - Toast **«Проект удалён»**
   - Карточка исчезает из списка
   - Счётчик лимита уменьшается
6. При ошибке:
   - Toast **«Ошибка при удалении проекта»**

---

## Сценарий 15: Настройки — Кастомные сервисы (создание)

1. Вкладка **«Кастомные сервисы»**
2. Нажимает **«Добавить»** → открывается диалог
3. Заполняет:
   - Название (обязательное)
   - Часы (число)
   - Фиксированная стоимость (опционально)
   - Иконка (PNG/SVG) — через загрузку файла
4. Нажимает **«Сохранить»**
5. Вызывается `POST /api/custom-services`
6. Перед созданием проверяется `custom_services_limit`:
   - Если лимит исчерпан → ошибка 403
7. Иконка загружается через `POST /api/custom-services/upload-icon` → Supabase Storage бакет `custom-service-icons`
8. При успехе: Toast **«Сервис создан»** → сервис появляется в списке

## Сценарий 16: Настройки — Кастомные сервисы (редактирование/удаление)

3. **Удаление:**
   - Вызывается `DELETE /api/custom-services?id={id}`

## Сценарий 24: Расчёт стоимости (алгоритм)

1. Пользователь нажимает **«Рассчитать»** на шаге 5
2. Сервер выполняет `POST /api/calculate`:
   - **Шаг 1:** Для каждого сервиса берутся часы (user → global), для кастомных — из custom_services → `total_base_hours`
   - **Шаг 2:** `total_base_hours` равномерно делится между активными ролями
   - **Шаг 3:** Для каждой роли применяется коэффициент технологии (через TECH_ROLE_MAP)
   - **Шаг 4:** Стоимость = скорректированные часы × ставка (user → global) + фиксированные стоимости кастомных сервисов
   - **Шаг 5:** Календарное время = total_adjusted_hours / (total_people × 8)
3. Возвращается JSON с `total_cost`, `calendar_days`, `roles`, `services`
4. На странице результата отображаются все данные

---

## Сценарий 25: Экспорт в PDF

1. На странице результата нажимает **«Экспорт в PDF»**
2. Вызывается `POST /api/export/pdf` с данными проекта
3. Сервер проверяет тариф пользователя:
   - Если `free` → добавляется водяной знак «MVP Calculator Demo»
4. Генерируется HTML с:
   - Логотипом и датой
   - Сводными данными (стоимость, часы, время)
   - Таблицами сервисов и ролей
   - Подвалом
5. Открывается `window.print()` → пользователь сохраняет как PDF
6. Toast **«PDF скачан»**

---

## Сценарий 26: Сохранение состояния конструктора

1. Пользователь заполняет шаги конструктора
2. Закрывает браузер или обновляет страницу
3. Данные сохраняются в `localStorage` (zustand persist middleware)
4. При повторном открытии `/projects/new` или `/projects/[id]/edit` данные восстанавливаются
5. Кнопка «Отмена» на шаге 1 → редирект на `/dashboard`
