# Plan: Автотесты и CI

**PRD:** [docs/prd-automated-tests-and-ci.md](prd-automated-tests-and-ci.md)
**Дата:** 2026-09-09

## Фазы реализации

### Фаза 1: Тестовый раннер и офлайн-запуск (Tracer Bullet)

**Цель:** появляется команда `npm test`, тесты выполняются локально без внешних сервисов.
**Затрагивает:** инфраструктура (инструментарий)
**Задачи:**
- [ ] Выбрать и настроить тестовый раннер и окружение для TypeScript-модулей проекта.
- [ ] Добавить скрипт `npm test` в `package.json`.
- [ ] Настроить моки Supabase-клиентов (`lib/supabase/*`), чтобы тесты работали офлайн и детерминированно.
- [ ] Добавить sanity-тест для проверки запуска набора.
**Тесты:** `npm test` зелёный на sanity-тесте, запускается без обращения к внешним сервисам.
**Когда готова:** критерий PRD №1 (каркас) — тесты запускаются офлайн.

### Фаза 2: Юнит-тесты ядра расчёта

**Цель:** ключевые сценарии расчёта защищены от регрессий.
**Затрагивает:** backend
**Задачи:**
- [ ] Покрыть сценарий 24 (расчёт стоимости) и особые случаи ТЗ п.7.3: приоритеты user→global по ставкам и часам, кастомные сервисы и их фиксированные стоимости, коэффициенты технологий по ролям, календарные дни.
- [ ] Покрыть особые случаи: отсутствие ставки у роли → 0, пустой выбор ролей.
- [ ] Проверить детерминированность: многократный прогон даёт стабильные результаты.
**Тесты:** эталонные наборы входных данных → ожидаемые результаты; N-кратный прогон без «плавающих» значений.
**Когда готова:** критерий PRD №2 — сценарий 24 и особые случаи покрыты, тесты детерминированы.

### Фаза 3: Тесты валидаций и прав доступа API

**Цель:** невалидные входные данные и неправомерный доступ отклоняются предсказуемо.
**Затрагивает:** backend
**Задачи:**
- [ ] Покрыть Zod-валидации `/api/calculate` и `/api/projects`: корректные данные проходят, невалидные отклоняются.
- [ ] Покрыть проверки прав API-роутов на моках Supabase: неавторизованный → 401, не-администратор на админ-эндпоинтах → 403.
**Тесты:** кейсы «невалидные данные отклоняются» и «права доступа соблюдаются» на моках.
**Когда готова:** критерий PRD №3.

### Фаза 4: CI-пайплайн

**Цель:** регрессии отлавливаются автоматически на каждом push/PR.
**Затрагивает:** инфраструктура (CI)
**Задачи:**
- [ ] Добавить CI-конфигурацию: на push и pull request выполняются `npm run lint`, `npx tsc --noEmit`, `npm test`.
- [ ] Продемонстрировать работу: намеренно сломанная проверка (изменённое эталонное значение) валит пайплайн, фикс возвращает зелёный статус.
**Тесты:** прогон CI: зелёный на актуальной ветке, красный при намеренной поломке.
**Когда готова:** критерии PRD №4 и №5.
