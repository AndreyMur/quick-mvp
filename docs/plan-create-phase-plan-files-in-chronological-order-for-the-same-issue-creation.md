# Plan: Файлы планов фаз в хронологическом порядке для создания issues

**PRD:** [docs/prd-explore-the-project-and-create-several-prds-for-changes-and-continuation-of-development-of-the-mvp-calculation-service.md](prd-explore-the-project-and-create-several-prds-for-changes-and-continuation-of-development-of-the-mvp-calculation-service.md)
**Дата:** 2026-09-09

## Цель

Получить набор файлов `docs/plan-*.md` (по одному на каждую фичу развития из PRD) и общий хронологический порядок их исполнения, чтобы бэклог можно было создавать на GitHub через issues-скилл («план → milestone на фазу, issue на задачу») для каждого файла в осмысленной последовательности.

## Хронологический порядок (roadmap)

Порядок исполнения файлов планов и зависимостей. Фундамент (план «Стабильность и техдолг») идёт первым и обязателен; после него остальные планы независимы и могут исполняться параллельно.

| Шаг | Файл плана | Фазы (milestones) | Условие запуска |
|---|---|---|---|
| 0 | `docs/plan-stability-and-technical-debt.md` | 1. Кодировка · 2. Репозиторий/доки · 3. Каскадное удаление · 4. Деплой | Стартует сразу |
| 1 | `docs/plan-connect-next-intl.md` | 1. Подключение (bullet) · 2. Публичные/auth-экраны · 3. Кабинет/конструктор · 4. Форматы + автоконтроль | После шага 0 (кодировка `ru.json` и файлов) |
| 2 | `docs/plan-calculation-engine-v2.md` | 1. Чистое ядро · 2. Веса и версия · 3. Совместимость/контракт · 4. UI весов | После шага 0; параллельно шагу 1 |
| 3 | `docs/plan-automated-tests-and-ci.md` | 1. Раннер (bullet) · 2. Тесты расчёта · 3. Валидации/доступ · 4. CI | После шага 0; после шага 2 — тесты пишутся на чистое ядро |
| 4 | `docs/plan-real-pdf-export.md` | 1. PDF (bullet) · 2. Полный шаблон · 3. Водяной знак · 4. Клиент | После шага 0; независим |
| 5 | `docs/plan-monetization-pro-business.md` | 1. Модель подписки · 2. Провайдер · 3. Pricing · 4. Сквозная проверка | После шага 0 и шага 4 (затрагивает водяной знак) |

Каждый файл плана самодостаточен: остановиться можно после любой его фазы, каждая фаза даёт рабочий результат.

## Фазы реализации

### Фаза 1: Создание файлов планов фаз по каждому PRD

**Цель:** у каждой фичи развития из `docs/prd-*.md` есть план с независимыми фазами, готовый для создания issues.
**Затрагивает:** документация (docs)
**Задачи:**
- [ ] Создать `docs/plan-stability-and-technical-debt.md` по PRD «Стабильность и техдолг».
- [ ] Создать `docs/plan-connect-next-intl.md` по PRD «Подключение i18n».
- [ ] Создать `docs/plan-calculation-engine-v2.md` по PRD «Ядро расчёта v2».
- [ ] Создать `docs/plan-real-pdf-export.md`, `docs/plan-automated-tests-and-ci.md` и `docs/plan-monetization-pro-business.md` по соответствующим PRD.
- [ ] В каждом плане: не больше 5 задач в фазе, backend и frontend одной фичи — разные фазы, первая фаза — минимальный рабочий путь (Tracer Bullet), в каждой фазе запланированы тесты.
**Тесты:** перекрёстная сверка: каждый критерий готовности PRD покрыт хотя бы одной фазой плана (таблица «Покрытие критериев»), задач вне скоупа PRD нет.
**Когда готова:** в `docs/` существуют 6 файлов `plan-*.md`, покрывающих все критерии своих PRD.

### Фаза 2: Установление хронологического порядка

**Цель:** зафиксирован порядок исполнения планов и создания issues, понятны зависимости.
**Затрагивает:** документация (docs)
**Задачи:**
- [ ] Упорядочить 6 планов по зависимостям (фундамент → независимые направления → монетизация) в таблице «Хронологический порядок».
- [ ] Оформить этот файл-roadmap со ссылками на каждый план.
- [ ] Сверить, что все фазы всех планов имеют рабочий результат и независимы (остановка после любой фазы допустима).
**Тесты:** каждый из 6 файлов планов существует и доступен по ссылке из roadmap; порядок фаз внутри планов хронологичен, между планами нет скрытых циклических зависимостей.
**Когда готова:** roadmap отражает полную последовательность шагов 0–5, issues-скилл можно применять к каждому файлу плана в этом порядке.
