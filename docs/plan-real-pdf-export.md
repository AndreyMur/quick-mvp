# Plan: Настоящий экспорт в PDF

**PRD:** [docs/prd-real-pdf-export.md](prd-real-pdf-export.md)
**Дата:** 2026-09-09

## Фазы реализации

### Фаза 1: Серверная генерация PDF — минимальный путь (Tracer Bullet)

**Цель:** заменить HTML/`window.print()`-заглушку на скачивание настоящего PDF без изменения клиентского вызова.
**Затрагивает:** backend
**Задачи:**
- [ ] Реализовать генерацию PDF в `app/api/export/pdf/route.ts` через `@react-pdf/renderer` на основе снапшота проекта (`projects.data`), сохранив контракт вызова клиента.
- [ ] Собрать минимальный шаблон: заголовок с логотипом и датой, сводные показатели (стоимость, часы, календарные дни).
**Тесты:** тест эндпоинта: ответ имеет `Content-Type: application/pdf`, файл валиден и открывается без диалога печати; в содержимом присутствуют сводные данные проекта.
**Когда готова:** критерий PRD №1 и основа №2 — API возвращает настоящий валидный PDF.

### Фаза 2: Полный шаблон отчёта

**Цель:** отчёт содержит всю детализацию из PRD, корректную кириллицу и многостраничную вёрстку.
**Затрагивает:** backend
**Задачи:**
- [ ] Добавить в шаблон таблицу сервисов (название, часы, стоимость).
- [ ] Добавить таблицу ролей (роль, ставка, часы, коэффициент, стоимость) и фиксированные стоимости кастомных сервисов.
- [ ] Добавить подвал «Сгенерировано в MVP Calculator».
- [ ] Обеспечить корректное отображение кириллицы (шрифты с поддержкой кириллицы) и разбиение длинного отчёта на страницы.
**Тесты:** тесты содержимого PDF: присутствуют все секции и подвал; проверка кириллицы без «кракозябр»/пустых квадратов; отчёт из 2+ страниц корректно разбивается, таблицы не обрезаются.
**Когда готова:** критерии PRD №2, №3 и №5.

### Фаза 3: Водяной знак по тарифу и производительность

**Цель:** тариф влияет на экспорт, генерация укладывается в лимит.
**Затрагивает:** backend
**Задачи:**
- [ ] Добавить водяной знак «MVP Calculator Demo» для тарифа `free` и его отсутствие для `pro`/`business` (проверка тарифа на сервере).
- [ ] Проконтролировать время генерации (≤ 5 секунд на реальном проекте).
**Тесты:** тест водяного знака для `free` и его отсутствия для `pro` (через установку тарифа в тестовой БД); замер времени генерации.
**Когда готова:** критерии PRD №4 и №6.

### Фаза 4: Клиентская интеграция без изменений

**Цель:** подтвердить, что экспорт со страницы результата работает как раньше (кнопка, скачивание, имя файла).
**Затрагивает:** frontend
**Задачи:**
- [ ] Проверить кнопку «Экспорт в PDF» на `/projects/[id]/result`: скачивание файла `project-name.pdf` с корректным содержимым.
- [ ] Убедиться, что клиентский код вызова экспорта не изменялся (регрессия контракта).
**Тесты:** smoke-сценарий экспорта реального сохранённого проекта; сравнение клиентского кода до/после (без изменений).
**Когда готова:** критерий PRD №7.

## Покрытие критериев готовности PRD

| №3 (корректная кириллица) | 2 |
| №4 (водяной знак free / без знака pro) | 3 |
| №5 (многостраничность) | 2 |
| №6 (генерация ≤ 5 сек) | 3 |
| №7 (клиентский вызов не изменён) | 4 |
