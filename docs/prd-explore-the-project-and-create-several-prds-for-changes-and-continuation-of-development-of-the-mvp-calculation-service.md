# PRD: Исследование сервиса и пакет PRD для развития MVP Calculator

**Дата**: 2026-09-09
**Статус**: Draft

## Цель

Зафиксировать результат исследования текущей реализации «MVP Calculator» (сервис расчёта MVP) и согласованный пакет PRD для изменения и продолжения разработки. Пакет даёт владельцу продукта единую точку входа в бэклог развития, а разработчику — проверяемые границы скоупа и критерии готовности по каждому направлению.

## Пользовательские сценарии

- Владелец продукта открывает сводку → видит направления развития, их приоритет, зависимости и файлы PRD.
- Разработчик берёт направление в работу → открывает соответствующий PRD и получает конкретный scope и критерии готовности.
- Разработчик начинает новую итерацию → использует сводку как навигатор, чтобы не потерять известные проблемы (кодировка, незакоммиченный код, «заглушка» PDF, нерабочий i18n).

## В скоупе

Пакет из 6 PRD по результатам аудита кода (`doc.md`, `scenario.md`, `task-plan.md`, `app/`, `components/`, `lib/`, `supabase/`):

| # | PRD-файл | Направление | Приоритет | Базис |
|---|----------|-------------|-----------|-------|
| 1 | `prd-stability-and-technical-debt.md` | Стабильность и техдолг | Высокий | Блокирует всё остальное |
| 2 | `prd-connect-next-intl.md` | Подключение i18n (next-intl) | Высокий | Уже заявлен в ТЗ как «готовность к мультиязычности» |
| 3 | `prd-calculation-engine-v2.md` | Ядро расчёта v2 | Высокий | Риск «равномерного распределения» из task-plan |
| 4 | `prd-real-pdf-export.md` | Настоящий экспорт в PDF | Средний | @react-pdf/renderer установлен, но не используется |
| 5 | `prd-automated-tests-and-ci.md` | Автотесты и CI | Средний | Тестов в репозитории нет; завязан на ядро расчёта v2 |
| 6 | `prd-monetization-pro-business.md` | Монетизация Pro/Business | Низкий (после стабильности) | Требует продуктовых решений (провайдер оплаты, валюта) |

Связи: PRD 1 — обязательный базис; PRD 5 тесно связан с PRD 3 (чистое ядро тестируемо); PRD 6 зависит от стабильного деплоя (PRD 1) и затрагивает логику лимитов и водяного знака, которые трогают PRD 2/4.

## Не в скоупе

- Реализация самих направлений (это отдельные PRD).
- Детальные UX-макеты и визуальные прототипы.
- Оценка трудозатрат и сроков по направлениям.
- Изменение требований базового ТЗ из `doc.md`.

## Технические ограничения

- Проект на Next.js **16.2.3** — конвенции App Router отличаются от Next.js 14, на которое ссылается ТЗ; перед кодом проверять доки в `node_modules/next/dist/docs/`.
- Текущее состояние кода: единый git-коммит, большая часть реализации не закоммичена; 10 файлов с русским текстом сохранены в cp1251.
- База — Supabase (PostgreSQL) с RLS; изменять схему только миграциями в `supabase/migrations/`.
- ТЗ оперирует условными единицами («у.е.»), реальная валюта не определена.

## Критерии готовности

- [ ] В папке `docs/` существует сводный файл (этот) и 6 PRD-файлов, перечисленных в таблице раздела «В скоупе».
- [ ] Каждый PRD заполнен по единой структуре (Цель, Пользовательские сценарии, В скоупе, Не в скоупе, Технические ограничения, Критерии готовности).
- [ ] Каждый PRD ссылается на реальные объекты кода/БД (имена файлов, функций, таблиц), проверенные по репозиторию.
- [ ] Критерии готовности в каждом PRD проверяемые (команда/скрипт/наблюдение), без формулировок «сделать хорошо».
- [ ] В PRD нет предписаний по способу реализации, только «что» и «зачем».
- [ ] Сводка прошла ревью владельца продукта: приоритеты и состав пакета согласованы.
