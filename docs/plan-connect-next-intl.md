# Plan: Подключение i18n (next-intl)

**PRD:** [docs/prd-connect-next-intl.md](prd-connect-next-intl.md)
**Дата:** 2026-09-09

## Фазы реализации

### Фаза 1: Подключение next-intl на одном экране (Tracer Bullet)

**Цель:** механизм локализации реально работает (конфигурация, локаль ru по умолчанию, dev-предупреждение о пропущенном ключе) на примере одного экрана.
**Затрагивает:** frontend
**Задачи:**
- [ ] Подключить `next-intl` к приложению: конфигурация, провайдер, локаль `ru` по умолчанию — без ошибок и deprecation-предупреждений.
- [ ] Перевести `messages/ru.json` в UTF-8 и синхронизировать структуру ключей с фактическим использованием.
- [ ] Вынести строки дашборда из компонентов в `messages/ru.json` и получать их через механизм локализации.
**Тесты:** приложение запускается без ошибок; дашборд отображает тот же текст; намеренно удалённый ключ вызывает видимое предупреждение в dev.
**Когда готова:** критерии PRD №1, №6 и часть №3/№4 (дашборд) — приложение работает с включённым next-intl, отсутствующий ключ виден в dev, ru.json валиден.

### Фаза 2: Публичные и авторизационные экраны

**Цель:** лендинг, формы входа/регистрации, тарифы и API-доки переведены на локализацию.
**Затрагивает:** frontend
**Задачи:**
- [ ] Вынести строки хедера и лендинга (`components/layout/header.tsx`, `app/page.tsx`, `app/layout.tsx`).
- [ ] Вынести строки форм авторизации и их ошибок/уведомлений (`components/auth/*`, страницы `/login`, `/register`).
- [ ] Вынести строки `/pricing` и `/api-docs`.
- [ ] Сверить, что текст на этих экранах идентичен прежнему (хардкоду).
**Тесты:** поиск кириллических строковых литералов по затронутым файлам не даёт результатов; экраны визуально совпадают с эталоном.
**Когда готова:** часть критерия №2 и №4 для публичных/auth-экранов — в затронутых файлах нет хардкод-кириллицы, текст прежний.

### Фаза 3: Кабинет и конструктор

**Цель:** дашборд, настройки, админка, конструктор (5 шагов) и страница результата полностью переведены на локализацию.
**Затрагивает:** frontend
**Задачи:**
- [ ] Вынести строки страниц `/dashboard`, `/settings` и `/admin` (включая диалоги и тосты).
- [ ] Вынести строки конструктора: `wizard-layout` и все 5 шагов (`components/builder/*`).
- [ ] Вынести строки страницы результата `/projects/[id]/result` и её уведомлений.
- [ ] Сверить текст всех экранов с прежним и убедиться в полноте ключей `messages/ru.json` для этих экранов.
**Тесты:** поиск хардкод-кириллицы по всему `app/*` и `components/*` пуст; перекрёстная сверка «ключ локали ⇄ используемый ключ» без пропусков.
**Когда готова:** критерии PRD №2, №3 и №4 полностью — нет кириллических литералов в UI-коде (кроме файлов локализации), ru.json покрывает все экраны, текст прежний.

### Фаза 4: Форматирование дат и чисел + автоконтроль

**Цель:** даты/числа форматируются по локали; отсутствие хардкод-строк проверяется автоматически.
**Затрагивает:** frontend
**Задачи:**
- [ ] Перевести форматирование дат и чисел (дашборд, страница результата, профиль) на механизмы локализации.
- [ ] Добавить правило/скрипт проверки отсутствия кириллических строковых литералов в отображаемом тексте (исключение — файлы локализации) и подключить к проверкам проекта.
**Тесты:** автотест форматирования даты/числа под локаль `ru`; скрипт проверки проходит на всём коде и «падает» при внесении хардкод-строки.
**Когда готова:** критерий PRD №5 и завершение №2 — даты/числа локализованы, хардкод-строки отлавливаются скриптом.
