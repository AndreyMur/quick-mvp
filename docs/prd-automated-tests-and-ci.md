# PRD: Автотесты и CI

**Дата**: 2026-09-09
**Статус**: Draft

## Цель

Добавить первый слой автоматических проверок и непрерывную интеграцию. Сейчас в репозитории нет ни одного теста, нет тестового скрипта и CI, при этом ядро расчёта (`lib/calculate.ts`) содержит бизнес-логику с нетривиальными случаями, а проект собирается на новой мажорной версии Next.js. Без тестов любые изменения расчёта, валидаций и API-роутов рискуют незаметно сломать уже реализованные сценарии из `scenario.md`.

## Пользовательские сценарии

- Разработчик меняет алгоритм расчёта → локальный прогон тестов показывает, какие эталонные результаты изменились и изменились ли они намеренно.
- Разработчик делает push/PR → CI автоматически прогоняет линт, проверку типов и тесты; при падении — PR не мержится.
- Поддержка приложения → регрессии в ключевых сценариях (расчёт, валидации, лимиты) обнаруживаются до попадания в прод.

## В скоупе

- Настройка тестового раннера и скрипта `npm test` (в `package.json` сейчас только `dev/build/start/lint`).
- Юнит-тесты ядра расчёта на фиксированных наборах входных данных: приоритеты user→global по ставкам и часам, кастомные сервисы и их фиксированные стоимости, коэффициенты технологий по ролям, календарные дни, особые случаи (нет ставки → 0, пустой выбор ролей). Согласовано с PRD «Ядро расчёта v2» — до его реализации тесты пишутся на текущее поведение с моками данных, после — на чистое ядро.
- Юнит-тесты Zod-валидаций в `lib/validations/` (входные контракты API).
- Тесты граничных проверок API-роутов (авторизация, проверка прав администратора) на моках Supabase-клиента.
- CI-пайплайн: на push и pull request выполняются `npm run lint`, проверка типов (`tsc --noEmit`) и `npm test`.

## Не в скоупе

- E2E-тесты на реальном браузере (Playwright/Cypress) — отдельная итерация.
- Нагрузочное и стресс-тестирование.
- Погонное покрытие всех UI-компонентов и админки в этой итерации (только критичные модули).
- Генерация отчётов о покрытии как обязательное условие мержа (достаточно метрики на ядре).

## Технические ограничения

- Тестового раннера в зависимостях нет — выбор и установка входят в работу.
- Supabase-клиенты (`lib/supabase/*`) требуют окружения; в юнит-тестах обращения к БД должны мокаться, чтобы тесты работали офлайн и детерминированно.
- Проект на Next.js 16.2.3: настройка тестового окружения для App Router и серверных модулей может отличаться от привычной для Next.js 14 — сверяться с `node_modules/next/dist/docs/`.
- Git-история сейчас содержит единственный коммит и большую часть кода не отслеживает (см. PRD «Стабильность и техдолг») — CI настраивать после коммита всей реализации.

## Критерии готовности

- [ ] `npm test` запускает все тесты без внешних сервисов (БД/Supabase замоканы) и завершается успешно.
- [ ] Ключевые сценарии расчёта из `scenario.md` (сценарий 24 и особые случаи из ТЗ п.7.3) покрыты тестами; тесты детерминированы (многократный прогон стабилен).
- [ ] Zod-валидации входных данных `/api/calculate` и `/api/projects` покрыты кейсами «невалидные данные отклоняются».
- [ ] CI-конфигурация в репозитории: на push и PR выполняются `npm run lint`, `npx tsc --noEmit`, `npm test`.
- [ ] CI зелёный на актуальной ветке; одна намеренно сломанная проверка (например, изменённое эталонное значение) приводит к падению пайплайна — проверено демонстрацией.
