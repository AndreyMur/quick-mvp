# Plan: Монетизация Pro/Business

**PRD:** [docs/prd-monetization-pro-business.md](prd-monetization-pro-business.md)
**Дата:** 2026-09-09

## Фазы реализации

### Фаза 1: Модель подписки и источник тарифа

**Цель:** тариф и лимиты определяются единым серверным механизмом на основе данных подписки, готовым к реальным платежам.
**Затрагивает:** backend, database
**Задачи:**
- [ ] Добавить миграцией объект данных подписки (план, статус, период, идентификатор провайдера) с RLS: пользователь — только своя запись, администратор — все.
- [ ] Реализовать серверный механизм определения активного тарифа и лимитов (проекты, кастомные сервисы, водяной знак PDF) на основе подписки.
- [ ] Перевести существующие проверки лимитов и водяного знака на этот механизм.
**Тесты:** юнит-тесты определения активного тарифа/лимитов для статусов подписки; проверка RLS от имени пользователя и администратора.
**Когда готова:** фундамент критериев №1, №2, №5 и №7 — тариф/лимиты берутся из подписки, RLS работает.

### Фаза 2: Интеграция платёжного провайдера (тестовый режим)

**Цель:** пользователь может оплатить план; события подписки обрабатываются надёжно.
**Затрагивает:** backend
**Задачи:**
- [ ] Создать платёжные сессии (checkout) для планов Профессиональный и Бизнес в тестовом режиме провайдера (цены согласованы: Pro 99, Business 299).
- [ ] Обрабатывать события webhook с проверкой подписи и идемпотентностью.
- [ ] Реализовать переходы по событиям: оплата → активация плана; отмена/окончание периода → возврат на `free`.
**Тесты:** тесты обработки webhook: оплата активирует план, отмена/окончание возвращает `free`, повторная доставка события не дублирует изменения, неверная подпись отклоняется.
**Когда готова:** критерии PRD №3 и №4.

### Фаза 3: Страница тарифов и состояния платежа

**Цель:** пользователь видит активные кнопки и корректное состояние своего плана.
**Затрагивает:** frontend
**Задачи:**
- [ ] Активировать кнопки выбора плана на `/pricing` (переход в checkout провайдера).
- [ ] Отображать «Текущий тариф» и статус/дату окончания подписки; исключить повторную оплату уже активного плана.
- [ ] Обработать прерванный/неудачный платёж: тариф не меняется, показывается понятное сообщение.
**Тесты:** тесты компонентов: состояние кнопок в зависимости от тарифа, экран ошибки/отмены платежа, блокировка повторной оплаты активного плана.
**Когда готова:** критерии PRD №5 и №6.

### Фаза 4: Сквозная проверка монетизации

**Цель:** покупка и отмена подписки корректно меняют тариф, лимиты и экспорт PDF.
**Затрагивает:** backend, frontend
**Задачи:**
- [ ] Проверить сквозной сценарий: тестовая оплата Профессионального плана → тариф `pro`, лимит проектов 20, PDF без водяного знака.
- [ ] Проверить сквозной сценарий: оплата Бизнес → тариф `business`, создание проектов не ограничено лимитом `free`.
- [ ] Проверить возврат на `free` после отмены/окончания: лимиты и водяной знак восстанавливаются.
- [ ] Итоговые проверки: миграция применена, RLS проверена, `npm run lint` и `npx tsc --noEmit` без ошибок.
**Тесты:** e2e-сценарии покупки/отмены в тестовом режиме провайдера (критерии №1, №2, №3) и итоговые проверки №7.
**Когда готова:** критерии PRD №1, №2 и №7.
