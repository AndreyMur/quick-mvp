# PRD: Стабильность и техдолг

**Дата**: 2026-09-09
**Статус**: Draft

## Цель

Устранить блокеры надёжности текущей реализации «MVP Calculator», из-за которых код нельзя считать готовым к развитию и продакшену: битая кодировка русского текста в 10 файлах, потерянная в git часть реализации, некорректное удаление пользователя администратором и отсутствие деплоя. Без этого направления остальные PRD строятся на нестабильном фундаменте.

## Пользовательские сценарии

- Пользователь открывает `/`, `/login`, `/register`, `/pricing`, `/api-docs`, шаги конструктора → русский текст отображается корректно, без «кракозябр» (сейчас cp1251-файлы читаются как UTF-8).
- Администратор удаляет пользователя в `/admin` → удаляется учётная запись и все связанные данные; в БД не остаётся «сирот» (сейчас удаляется только запись в `profiles`, пользователь в `auth.users` остаётся).
- Разработчик клонирует репозиторий → получает всю реализацию и README с инструкцией запуска (сейчас большая часть кода не закоммичена).
- Посетитель заходит по публичному HTTPS-адресу → приложение работает в продакшене (сейчас деплой не выполнен, задача 11.3 из task-plan.md открыта).

## В скоупе

- Перекодирование 10 файлов из Windows-1251 в UTF-8: `app/layout.tsx`, `app/page.tsx`, `app/pricing/page.tsx`, `app/api-docs/page.tsx`, `components/layout/header.tsx`, `components/auth/sign-in-form.tsx`, `components/auth/sign-up-form.tsx`, `components/builder/wizard-layout.tsx`, `components/builder/step-summary.tsx`, `messages/ru.json`.
- Проверка остальных файлов с русским текстом на соответствие UTF-8; фиксация проверки в виде команды/скрипта.
- Коммит всей неотслеживаемой реализации (`app/`, `components/`, `lib/`, `i18n/`, `messages/`, `supabase/`, `middleware.ts` и пр.) и приведение README к реальному состоянию проекта.
- Полное удаление пользователя из админки: `auth.users` + связанные `profiles`, `projects`, `user_rates`, `user_service_hours`, `custom_services`.
- Устранение расхождения документации со схемой БД: в комментариях указано «9 таблиц», по факту 8.
- Деплой на Vercel (или собственный сервер): настройка переменных окружения, подключение Supabase, публичный HTTPS-URL.

## Не в скоупе

- Новая пользовательская функциональность.
- Рефакторинг архитектуры и перенос логики (см. отдельный PRD «Ядро расчёта v2»).
- Автотесты и CI (см. отдельный PRD).
- Подключение платных тарифов (см. отдельный PRD).

## Технические ограничения

- Проект на Next.js 16.2.3: конвенции отличаются от Next.js 14 из ТЗ; перед правками сверяться с `node_modules/next/dist/docs/`.
- Файлы в cp1251 до перекодирования могут некорректно обрабатываться линтером/SWC — перекодировать до прогона сборки.
- Удаление из `auth.users` требует привилегий сервисной роли; в репозитории уже есть неиспользуемый `lib/supabase/admin.ts`.
- RLS-политики используют функцию `is_current_user_admin()` (миграция `002_fix_rls_recursion.sql`).

## Критерии готовности

- [ ] Скрипт-проверка кодировки (декодирование как UTF-8) не находит ни одного файла `.ts/.tsx/.json` с русским текстом вне UTF-8; в том числе все 10 файлов из перечня.
- [ ] `npm run dev`: на `/`, `/login`, `/register`, `/pricing`, `/api-docs`, всех шагах конструктора и дашборде нет mojibake в русском тексте.
- [x] `git status` чист, вся реализация в истории, README описывает запуск и переменные окружения.
- [ ] Удаление пользователя через `DELETE`-эндпоинт админки удаляет запись из `auth.users` и связанные данные; повторный `GET` списка пользователей не содержит удалённого, в БД нет осиротевших `profiles/projects`.
- [x] Учёт количества таблиц в документации и `database.types.ts` соответствует фактической схеме (8 таблиц).
- [ ] Приложение доступно по публичному HTTPS-URL, вход на `/dashboard` и создание проекта работают в продакшене.
